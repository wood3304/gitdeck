## 界面总览

![界面总览](../docs/screenshots/changes.png)

GitDeck 的界面分为八个区域：

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| 顶栏 | 最上方 | 当前仓库面包屑、命令面板、主题切换 |
| 代码库栏 | 左侧上方 | 管理多个仓库，查看状态摘要 |
| 文件树 | 左侧下方 | 按层级浏览当前仓库文件，打开文件或文件历史 |
| 仓库头 | 右上顶部 | 仓库路径、当前分支、推送、刷新与 fetch |
| 标签栏 | 仓库头下方 | 在「更改 / 历史 / 文件历史 / 文件」之间切换 |
| 列表面板 | 中间偏左 | 文件、提交或文件版本列表 |
| 内容面板 | 右侧 | 文件编辑器，或当前选择的差异内容 |
| 提交/状态栏 | 左侧底部 / 最下方 | 提交信息、Git 版本与当前时间 |

### 顶栏

- 左侧显示 GitDeck 标识。
- 中间显示当前仓库和分支的路径。
- 右侧「快速查找」打开命令面板，也可以直接按 `Ctrl+K`。
- 最右侧太阳/月亮图标切换浅色/深色主题。
- `LOCAL ONLY` 表示所有数据都在本机处理。

### 代码库栏

每个仓库卡片显示：

- 仓库名称和首字母图标；
- 当前分支；
- 最近一次提交的相对时间；
- 未提交文件数量（右侧数字）；
- 领先/落后上游分支的提交数（`↑` / `↓`）；
- 有更改时图标右下角出现一个黄色小点；
- 当前选中的仓库使用左侧高亮边和渐变背景。

仓库数量超过两个时，顶部会出现筛选框。

点击卡片切换仓库；双击卡片在资源管理器中打开仓库目录。悬停卡片会显示 `…` 菜单，包含：

- 在文件管理器中打开；
- 复制仓库路径；
- 从工作台移除。

代码库列表下方是当前仓库的文件树。它占用剩余高度并可独立滚动，仓库较多时列表会自动限制高度。

### 仓库头

- 仓库名称、当前分支和路径；
- 「N 个更改」或「已同步」状态；
- 分支切换器；
- 推送 / 发布当前分支；
- 刷新状态；
- 获取远程更新；
- 更多菜单。

### 状态栏

底部显示：

- 当前代码库数量；
- 当前分支；
- Git 版本；
- 编码和主题。

## 代码库管理

### 添加代码库

有三种入口：

1. 左侧底部的「打开代码库」；
2. 代码库栏顶部标题旁的 `+`；
3. 快捷键 `Ctrl+O`。

打开目录浏览器后：

- 顶部路径栏可以直接输入路径，按 Enter 或「前往」；
- 左侧「快速访问」包含主目录、桌面、文档、工作区、磁盘；
- 主区域列出当前目录下的子文件夹；
- 带 `GIT` 标签的文件夹是 Git 仓库；
- 点击文件夹进入下一级；
- 点击仓库行的「添加」可以直接添加；
- 点击「添加此文件夹」会把当前目录作为仓库添加；
- 当前目录本身是仓库时，会显示「Git 仓库」徽标。

GitDeck 使用 `git rev-parse --show-toplevel` 解析仓库根目录。因此：

- 选择仓库内的任意子目录也可以；
- 选择 `.git` 目录也可以；
- 裸仓库（bare repository）会被拒绝，因为需要工作区才能展示更改。

重复添加同一仓库时，GitDeck 会给出提示并切换到已有仓库，不会产生重复项。

### 克隆远程代码库

打开同一个「打开代码库」弹窗，切换到「远程克隆」：

1. 输入 HTTPS 或 SSH 地址，例如：
   - `https://github.com/user/repo.git`
   - `git@github.com:user/repo.git`
   - `github.com/user/repo`（自动补全 `https://`）
2. 使用目录浏览器选择**目标父文件夹**；
3. 确认目录名，右侧会实时显示最终路径；
4. 点击「克隆并添加」。

GitDeck 会执行完整的 `git clone`，保留全部提交历史和远程配置，然后自动加入工作台。

注意：

- 目标目录必须不存在；已存在时会拒绝克隆，避免覆盖；
- 私有仓库的认证由系统 Git / Git Credential Manager 处理，建议先在终端成功执行一次 `git clone`；
- 地址中不允许携带账号或 Token（避免凭据写入 `.git/config`）；
- 克隆大仓库时可能需要几分钟；当前版本没有进度条和取消按钮，请保持窗口打开；
- 当前仅支持完整克隆，不支持浅克隆、稀疏检出或子模块初始化选项。

### 移除代码库

打开仓库卡片的 `…` 菜单，点击「从工作台移除」，在确认弹窗中确认。

这个操作 **只从 GitDeck 的列表移除**：

- 不会删除仓库；
- 不会执行 `git clean`；
- 不会修改 `.git`；
- 不会删除任何文件。

### 切换代码库

点击左侧仓库卡片即可切换。GitDeck 会：

- 记住当前仓库；
- 重新读取该仓库的状态和历史；
- 将标签页重置到「更改」。

### 仓库不可用

如果仓库目录被移动、删除或失去访问权限：

- 左侧卡片显示「不可用」；
- 仓库头显示 `—`；
- 不会阻塞其他仓库；
- 可以重新添加或从列表移除。

## 文件目录与编辑器

![文件树与编辑器](../docs/screenshots/file-editor.png)

### 文件树

文件树位于代码库列表下方，展示当前仓库的：

- 已跟踪文件；
- 未跟踪但未被 `.gitignore` 忽略的文件；
- 当前工作区中存在的目录。

不显示：

- `.git` 内部文件；
- 被 `.gitignore` 忽略的文件；
- 不存在的空目录。

操作：

- 点击目录行展开/收起；
- 顶层目录默认展开；
- 顶部筛选框输入路径片段，显示匹配文件的扁平列表；
- 点击文件行在右侧打开编辑器；
- 点击文件行右侧的时钟图标，直接进入该文件的文件历史；
- 点击文件树标题右侧的刷新按钮重新扫描。

文件树最多展示 10,000 个路径；超大仓库会在接口层标记截断。

### 打开文件

点击文件后：

- 顶部新增「文件」标签，标签名是文件名；
- 右侧显示带行号的文本编辑器；
- 顶部显示路径、语言、大小和 LF/CRLF；
- 点击「文件历史」直接查看这个文件的历史版本；
- 切换其他标签不会丢失未保存的草稿。

### 编辑与保存

- 直接修改文本；
- `Ctrl/Cmd+S` 或「保存」写入磁盘；
- 「撤销」恢复到磁盘内容；
- 有修改时顶部出现「未保存」，标签页出现黄色圆点；
- 保存后文件状态会变为「更改」，但不会自动暂存或提交；
- 到「更改」中勾选文件，再提交。

### 草稿恢复

编辑中的内容会按「仓库 + 文件路径」保存在当前浏览器会话：

- 切换到「文件历史」或其他文件后再回来，会提示「已恢复上次未保存的草稿」；
- 点击「放弃草稿」恢复磁盘内容；
- 保存或撤销后草稿会被清除；
- 关闭浏览器会话后草稿不再保留。

这是一个浏览器会话级保护，不是完整的自动保存。

### 行尾与编码

- 读取时检测原文件使用 LF 还是 CRLF；
- 编辑区统一显示 LF；
- 保存时按原文件的行尾格式写回；
- 文件按 UTF-8 文本读取；二进制文件自动只读；
- 最大可编辑 2 MB；超过时显示只读预览。

### 安全边界

编辑器会拒绝：

- 仓库外的路径；
- `.git` 目录内部文件；
- 指向仓库外的符号链接；
- 超过 2 MB 的文件；
- 含 NUL 的二进制内容。

这些限制在服务端执行，不依赖前端。

## 本地更改

### 文件分组

「更改」标签根据 Git 状态把文件分为四组：

| 分组 | 说明 |
| --- | --- |
| 已暂存 | 已进入 index，下一次提交会包含 |
| 更改 | 工作区有修改，但尚未暂存 |
| 未跟踪 | Git 尚未跟踪的新文件 |
| 冲突 | 存在合并冲突，需要先解决 |

一个文件可能同时出现在「已暂存」和「更改」中，例如已暂存后又继续修改（`MM`）。

### 状态标记

| 标记 | 含义 |
| --- | --- |
| `M` | 修改 |
| `A` | 新增 |
| `D` | 删除 |
| `R` | 重命名 |
| `C` | 复制 |
| `T` | 类型变化 |
| `U` | 冲突 |
| `?` | 未跟踪 |

文件行下方显示增删行数，例如 `+12 −3`。

### 暂存与取消暂存

每个文件左侧有一个方形复选框：

- 在「更改」或「未跟踪」中点击 → `git add`；
- 在「已暂存」中点击 → 取消暂存（`git restore --staged`）。

组标题右侧的「全部暂存 / 全部取消」仅作用于该组文件。

顶部工具栏中的 `+` 会暂存全部更改（包括未跟踪文件），`−` 会取消全部暂存。

### 丢弃更改

选中已跟踪文件后，Diff 面板右上角会出现垃圾桶图标。

确认后会执行：

- 已暂存但未提交的修改：重置 index 和工作区；
- 未提交的工作区修改：恢复为 `HEAD` 版本；
- 当前界面只在已跟踪文件上提供丢弃入口，未跟踪文件不会被删除。

> 丢弃不可撤销。请先确认 Diff。

### 筛选文件

列表上方搜索框会按路径过滤，不区分大小写。筛选只影响显示，不影响暂存操作。

## 查看与比较 Diff

### 比较模式

根据文件状态，Diff 面板顶部提供不同的比较范围：

| 模式 | 旧版本 | 新版本 | 使用场景 |
| --- | --- | --- | --- |
| 与 HEAD | HEAD | 工作区 | 查看此文件相对上一次提交的全部变化 |
| 未暂存 | 暂存区 | 工作区 | 查看尚未暂存的修改 |
| 已暂存 | HEAD | 暂存区 | 提交前核对将要提交的内容 |
| 未跟踪 | 空文件 | 工作区 | 查看新文件内容 |

如果文件同时有已暂存和未暂存修改，可以在这些范围之间切换。

### 并排与统一视图

右上角的两个图标：

- **并排（Split）**：左边旧版本、右边新版本，适合逐行 review；
- **统一（Unified）**：传统 patch 样式，适合窄窗口或复制粘贴。

选择会记录在浏览器本地存储中，下次打开保持。

### 词级高亮

对于成对的修改行，GitDeck 会计算词法差异，并高亮具体变化的 token，而不只是整行标红/绿。

### 完整上下文

默认显示 Git 生成的 3 行上下文。点击展开图标会重新请求完整上下文，适合理解大段代码中的局部改动。

再次点击可收起。

### 复制 Patch

点击「Patch」复制当前差异的原始文本或由 GitDeck 重建的 patch，方便粘贴到 issue、PR 或文档中。

### 二进制 / 空差异

- 二进制文件显示说明，不渲染文本；
- 内容未变化时显示「没有可显示的差异」；
- 文件被删除时仍会显示删除行。

## 提交

### 提交流程

1. 在「更改」中暂存需要提交的文件；
2. 在左下角输入提交信息；
3. 点击「提交」或按 `Ctrl+Enter`。

只有已暂存文件会被提交。

### 提交信息

- 支持多行；
- 右侧显示字符数；
- GitDeck 使用 `--cleanup=strip`，会清理首尾空白和多余空行；
- 提交信息为空时提交按钮不可用。

### 修正上一次提交

勾选「修正上次提交」后，执行 `git commit --amend -m <message>`。

注意：

- amend 会重写最近一次提交的 hash；
- 如果该提交已经推送到共享分支，请谨慎使用；
- 可以在没有暂存文件时仅修改提交信息；
- 如果 Git 钩子失败，错误会显示在 Toast 中。

### 失败处理

提交失败时，Toast 会显示 Git 的 stderr，例如：

- 未配置 `user.name` / `user.email`；
- pre-commit hook 失败；
- 合并冲突未解决；
- 没有可提交内容。

点击 Toast 中的「查看详情」可以看到完整输出。

## 提交历史

### 分支范围

- **当前分支**：只显示当前 HEAD 可达的提交（默认）；
- **全部分支**：显示所有本地分支、远程分支和标签可达的提交。

### 搜索

按提交信息过滤，使用 `git log --grep`，不区分大小写，按固定字符串匹配。

### 提交列表

每行显示：

- 提交主题；
- 作者；
- 相对时间；
- 短 hash；
- 标签、分支、远程引用；
- 合并提交标记。

左侧的竖线和圆点提供简单的时间线视觉引导。

### 提交详情

选中提交后，右侧显示：

- 完整提交主题；
- 提交正文（如果有）；
- 作者头像首字母、姓名、邮箱；
- 提交时间；
- 变更文件数、新增/删除行数；
- 标签和分支引用；
- 合并提交提示（与第一个父提交比较）；
- 变更文件列表；
- 当前选中文件的 Diff。

### 文件列表

点击文件行切换 Diff。文件较多时，列表头会出现筛选框。

文件行右侧的时钟图标会打开该文件在文件历史视图中的时间线，并自动选中当前提交。

### 复制哈希

右上角「复制哈希」会复制完整 40/64 位 commit SHA。

## 文件历史

### 打开方式

1. 点击顶部「文件历史」标签（会使用当前选中的文件）；
2. 在「更改」中点击文件行的时钟图标；
3. 在「提交历史」中点击提交文件行的时钟图标；
4. 在左侧文件树中点击文件行的时钟图标；
5. 在文件编辑器中点击「文件历史」。

后四种方式会自动带入文件路径；从提交历史进入时还会带入当前提交。

### 选择文件

在路径输入框中输入文件路径。输入时会显示匹配的已跟踪文件，支持：

- 按路径片段匹配；
- 按文件名匹配；
- 点击建议项直接打开；
- 按 Enter 选择第一个建议；
- 按 Esc 关闭建议列表。

路径使用仓库内的相对路径，例如 `src/App.jsx`。

### 版本时间线

- 最新版本在最上方；
- 显示提交主题、作者、相对时间和短 hash；
- 第一项标记「最新」；
- 通过 `git log --follow` 跟随文件重命名；
- 最多展示最近 80 个版本。

### 查看某个版本的改动

默认「此版本变更」会显示：

- 该提交的父提交 → 该提交；
- 对于初始提交，显示空文件 → 初始版本。

切换到「与工作区」会显示：

- 该历史版本 → 当前工作区文件；
- 适合确认一段历史代码在今天的文件里变成了什么样。

### 边缘情况

- **未跟踪文件**：工作区存在但没有历史，会提示「文件尚未被追踪」；
- **无历史**：路径存在但没有提交记录；
- **路径不存在**：请检查拼写或使用建议列表；
- **二进制文件**：显示状态，不渲染文本；
- **重命名**：历史列表会跟随，但历史版本 Diff 仍以当前路径为准。

## 比较两个版本

1. 点击文件历史顶部的「对比版本」；
2. 左侧每个版本出现复选框；
3. 勾选两个版本；
4. 右侧自动请求 `git diff <较旧版本> <较新版本> -- <path>`；
5. 顶部显示 `旧 hash → 新 hash`；
6. 点击「退出对比」返回单版本模式。

如果先选择较新的版本、再选择较旧的版本，GitDeck 会按时间顺序自动排列，始终显示「较旧 → 较新」。

版本对比适合：

- 确认某个重构在两版之间到底改了什么；
- 比较两个发布标签；
- 查看一段代码在多个提交之间的累计变化。

---

## 历史文件快照

在文件历史的单个版本模式下，点击右上角「查看此版本」。

弹窗中显示：

- 文件路径；
- 提交短 hash；
- 文件大小；
- 完整文本内容；
- 行号。

支持「复制内容」和「重新读取」。

限制：

- 最大读取 2 MB；
- 二进制文件不显示内容；
- 超过 4,000 行时只展示前 4,000 行；
- 内容通过 `git show <rev>:<path>` 读取，不会修改工作区。

## 分支、推送与远程更新

### 分支切换

点击仓库头中的分支按钮：

- 顶部搜索框过滤分支；
- 本地分支显示当前标记；
- 点击本地分支执行 `git switch <branch>`；
- 远程分支点击后会创建一个同名本地分支并跟踪它；
- 「新建分支」基于当前 HEAD 执行 `git switch -c <name>`；
- 分支名由 `git check-ref-format --branch` 校验。

如果工作区存在会冲突的修改，Git 会拒绝切换并显示错误。

### 推送当前分支

仓库头中有一个带云上传图标的「推送」按钮：

- 已有上游分支时，按钮显示「推送」以及领先提交数，点击执行 `git push`；
- 首次推送时，按钮显示「发布分支 / NEW」，点击后打开发布弹窗；
- 在发布弹窗中选择远程仓库，GitDeck 会执行 `git push --set-upstream <remote> <branch>`，并自动建立跟踪关系；
- 推送成功后刷新仓库摘要、ahead/behind 和分支状态；
- 推送失败时不会自动重试或强推，Git 的原始 stderr 会显示在 Toast 中。

GitDeck 不提供 force push、标签推送和 pull。遇到 `non-fast-forward` 时，请先 fetch，再在终端或外部工具中合并/变基。

![发布当前分支](../docs/screenshots/push-branch.png)

### 获取远程更新

点击云下载图标执行：

```bash
git fetch --all --prune
```

成功后状态和仓库摘要会刷新。GitDeck 不会自动 merge 或 rebase，也不会修改工作区。

> GitDeck 禁用了终端交互式凭据输入；Git 凭据由系统 Git / Git Credential Manager 处理。若 fetch 或 push 因认证失败，请先在终端完成一次对应的 Git 操作，再回到 GitDeck 重试。

## 典型工作流

### 提交前 review

1. 打开「更改」；
2. 在「未跟踪」中确认新文件；
3. 逐个点击文件，使用「与 HEAD」检查完整变化；
4. 暂存；
5. 切换到「已暂存」，使用「已暂存」模式确认将提交的内容；
6. 填写提交信息并提交。

### 查找一段代码的来历

1. 切换到「历史」；
2. 搜索相关关键词，或选择「全部分支」；
3. 打开提交详情；
4. 点击变更文件，查看该提交的具体改动；
5. 若需要更早的历史，点击文件行时钟图标进入文件历史；
6. 继续沿时间线向前查看。

### 比较某个文件的两版

1. 进入「文件历史」；
2. 输入文件路径；
3. 点击「对比版本」；
4. 勾选两个版本；
5. 查看差异，或导出 patch。

### 同时管理多个项目

1. 使用 `Ctrl+O` 或左下角按钮添加多个仓库；
2. 左侧卡片会显示各自的更改数和分支状态；
3. 点击卡片切换；
4. 顶部「刷新所有仓库」会更新全部摘要。

## 大仓库与性能

GitDeck 使用 Git CLI，因此性能主要取决于仓库大小和磁盘速度。

当前策略：

- 状态文件最多返回 5,000 条，超出会截断并标记；
- 提交历史每页 60 条，可加载更多；
- 文件历史最多 80 个版本；
- 文件树最多 10,000 个路径；
- 可编辑文件最大 2 MB；
- Diff 默认 3 行上下文；
- 历史文件快照最大 2 MB；
- 目录浏览每层最多 500 个文件夹；
- Git 命令默认 30 秒超时，fetch / push / clone 为 180–300 秒。

如果仓库包含大量未跟踪文件，建议先配置 `.gitignore`，再刷新。

## 安全与隐私

- 服务只监听 `127.0.0.1`。
- 不发送遥测，不加载远程字体或第三方脚本。
- 不读取 Git 凭据；凭据由系统 Git 管理。
- 文件编辑器只允许编辑仓库内普通文本文件，拒绝 `.git` 路径、目录穿越和指向仓库外的符号链接。
- 删除仓库不会删除文件。
- 丢弃修改前有确认。
- 不要将端口映射到公网或不可信网络；服务没有登录鉴权。
- 如果多人共用这台机器，请理解：任何能访问 `127.0.0.1:4788` 的本地进程都可以调用写操作 API。

## 常见问题

### Q: 为什么首次启动没有示例仓库？

`demo/` 目录不随源码提交（嵌套 `.git` 无法直接纳入父仓库）。请运行：

```bash
npm run seed -- --force
```

再启动应用，或手动添加生成的目录。

### Q: 为什么提交按钮是灰色的？

可能原因：

- 提交信息为空；
- 没有已暂存文件，且没有勾选 amend；
- 正在提交中。

### Q: 为什么切换分支失败？

工作区有与目标分支冲突的修改。先提交、暂存或丢弃这些修改，或使用 Git 终端处理。

### Q: 为什么 fetch 没有输出？

如果仓库没有配置远程，`git fetch --all` 会成功但不产生输出。GitDeck 会提示已同步。

### Q: push 失败怎么办？

- 确认仓库配置了远程：`git remote -v`；
- 认证失败时，先在终端执行一次 `git push`，让系统 Git 凭据管理器完成登录；
- 遇到 `non-fast-forward` 时，先 fetch，再合入或变基；GitDeck 不会强制推送；
- detached HEAD 状态下先切换到本地分支。

### Q: 能查看某个文件某个提交的完整内容吗？

可以。文件历史 → 选择版本 → 「查看此版本」。这是只读快照。

### Q: 能直接 push 吗？

可以。点击仓库头的「推送」按钮即可。首次推送需要选择远程仓库，GitDeck 会自动设置上游分支。暂不支持 force push 和 pull。

### Q: 编辑并保存后，为什么“更改”里没有自动暂存？

保存只写入工作区，不会执行 `git add`。请到「更改」中勾选文件，再提交。这是刻意设计，避免编辑器保存触发意外暂存。

### Q: 为什么文件树不显示 `node_modules` 或构建目录？

文件树只显示已跟踪文件和未被 `.gitignore` 忽略的未跟踪文件。若目录被忽略，它不会出现；这是大仓库保持可用的默认行为。

### Q: 未保存的编辑内容去哪了？

当前浏览器会话内，草稿按「仓库 + 文件路径」保存在 `sessionStorage`。切换标签或文件再回来可以恢复。关闭浏览器会话或手动「放弃草稿」后不会保留。

### Q: 克隆远程代码库失败怎么办？

- 目标目录已存在：换一个目录名；
- 私有仓库认证失败：先在终端执行一次 `git clone`，让系统 Git 凭据管理器完成登录；
- URL 包含账号或 Token：移除凭据部分，使用系统凭据管理器；
- 大仓库超时：当前 clone 超时为 300 秒，建议在终端克隆后通过「本地仓库」添加。

### Q: 数据保存在哪里？

`.data/state.json`，只包含仓库路径和当前选中项。删除该文件不会影响仓库。

### Q: 是否支持 Windows 以外的平台？

支持。macOS / Linux 下使用相同的 Node.js 服务，Git 命令通过管道捕获；Windows 下使用文件捕获以避开管道和编码问题。
